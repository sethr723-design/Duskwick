# Duskwick

A browser game (three.js r128, no build step). Open `index.html` by double-clicking. It loads `js/*.js` in order as
plain `<script>` tags that all share one global scope. Player-facing notes and the changelog live in `README.txt`.

## Working rules
- **The user tests.** Don't run or play-test the game unless asked. After an edit, only syntax-check the file you touched:
  `& 'C:\Program Files\nodejs\node.exe' --check js\<file>.js`
  (Node is installed, but `node` isn't on PATH in this app, so use the full path.)
- three.js is **r128**: newer helpers don't exist (e.g. `BufferGeometry.applyQuaternion`; use
  `applyMatrix4(new T.Matrix4().makeRotationFromQuaternion(q))`). One bad call in a model builder used by `world()`
  stops the whole world from building (v44: only 2 foes, `ffm` errors every frame).
- Keep requests small and focused. Read only the file you need; use Grep to find the place first.
- Update `README.txt` (top section) when you add a player-visible feature.
- No git yet. `index.backup-v11.html` is the last single-file version, kept as a fallback.
- Prettier format, 120 columns: `npx prettier@3.3.3 --print-width 120 --write js/<file>.js` (put `C:\Program Files\nodejs` on PATH first).
- **Before adding any new top-level name, grep all `js/*.js` for it.** Every file shares one global scope: a second
  `const`/`let` with an existing name makes the browser skip that WHOLE file (seen as "X is not defined" elsewhere).
  `node --check` per file can't catch this. Names already taken that bit us: `SHOPS` (shop stock, 06), `GB` (gear, 07).

## Load order matters
The files run top to bottom in this order, so **top-level code can only use things from the same file or earlier files**.
Function declarations no longer hoist across files. Inside functions that run later (event handlers, the game loop,
battle code), anything is fine. If world-building code needs a later function, wrap it: `() => towerReset()`.

## Rules that keep saves and multiplayer working
- **Never reorder or delete `QS` entries.** Saves store quest progress by index. Append new quests at the end
  (22-31 are the role quests). The `q:` field on a spell points at a quest index.
- New save fields: add a default in `DEFP` (old saves are merged over it in `ld`).
- v30: a quest whose item reward doesn't fit still completes; the item index waits in `P.qhold` and `qhGive()` (06,
  called at the top of `qchk`) hands it over when the bag has room. Body class `bsay` is set while a boss/road-boss
  speech box (32/33) is up (fades `#tut`). The floating "Press E" prompt is `#epr` (11), hidden under `body.cut`.
  Tower stairs stay open and the Warden (`f.tw === 3`) stays dead once `P.warden > 0`.
- World generation must stay deterministic: use the seeded `rnd/rr` (or a separate fixed-seed stream like `rb`),
  never `Math.random`, for anything that places geometry, solids or foes.
- Combat is party-shaped: `g.heroes[0]` is the local player (`g.hp` is their HP). Never assume the player is alone:
  pick targets from `g.heroes`, end a fight with `partyDown()`, and send player actions through `NET.send('act', ...)`.
- v12: each element is one class and the class fixes the role. `P.cls` pyre/gale/rime/verdant/spirit →
  element `CLE` (fire/storm/ice/heal/spirit) and role `CLR` (damage/aoe/tank/healer/summoner). `syncRole()` enforces it
  in `startGame`; there is no role picker (`pickRole` just syncs). Role spells have `rl:`; `sch:1` spells take `schEl()`.
  Role-spell visuals per element live in `RFX` (09-party.js).
